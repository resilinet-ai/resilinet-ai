## Data

- **Training:** 400,000 transactions, SandboxBank generator, development seed 31000, batches [0, 1, 2, 3, 4, 5, 6, 7], 5,000 accounts and 500 merchants.
- **Hold-out:** batches [8, 9] of the same seed, never seen in training. Evaluation seeds (100,000 to 199,999) are never used: they belong to the registered benchmark.
- **Fraud** is the generator's: about 0.2% of transactions, with their own channel mix, larger amounts, more declines and more high-risk merchant categories. The model learns these rules back; real fraud is not like this.

## Features

`amount`, `amount_to_limit`, `channel` (categorical), `credit`, `status` (categorical), `account_type` (categorical), `has_merchant`, `merchant_category` (categorical). The label is the target only.

## Rebuild and check

```bash
uv sync --package rai-sandboxbank --extra model
uv run sandboxbank model card --out sandboxbank/MODEL_CARD.md   # retrains, re-scores
uv run sandboxbank model score --feed <feed folder> --batch <file> --out scores.csv
```

The same recipe and scikit-learn version give the same model. The fingerprint can differ across platforms in the last digits of floating point; the recipe SHA-256 cannot.

## Limitations

- Trained and tested on one synthetic generator; it has never seen real data.
- No fairness analysis: the synthetic data has no protected attributes.
- Not calibrated beyond what gradient boosting gives; scores rank, they are not probabilities to act on.
