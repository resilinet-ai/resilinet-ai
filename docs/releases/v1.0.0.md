# RAI v1.0.0

> Status: draft. The release procedure ([releasing](../releasing.md)) removes this line once the day-90 conditions hold: baselines B1 and B2 frozen, the protocol registered and the S01–S20 registry sealed. Until then, the workflow "Release" refuses the tag.

RAI (ResiliNet AI) checks data pipelines and their recovery before release, and keeps the evidence. v1.0 is the version the study's benchmark runs against: it is frozen before any benchmark run (Build Plan, section 9). All data it ships with or generates is synthetic (SandboxBank).

## What v1.0 does

**Validate data before it moves on**

- YAML data contracts with severities and thresholds; a critical failure fails the run (FR-03.1, FR-03.4).
- Duplicates within and across batches, schema drift as breaking or not (FR-03.2, FR-03.3).
- Connectors for CSV, Parquet and PostgreSQL, with credentials only as secret references (FR-02.1, FR-02.3). Redshift: built, not yet run against a live cluster (FR-02.2).
- Lineage edges with the SHA-256 of every input (FR-04.1), and an orchestrator's jobs in a project's graph through OpenLineage (FR-04.2).
- A privacy sentinel: synthetic canary values found in data, logs and evidence bundles, every hit masked (FR-05.1).
- Model evaluation with sample sizes and confidence intervals, drift checks (PSI, KS), and robustness tests that perturb a model's inputs and judge how much each metric degrades (FR-09.1, FR-09.2, FR-09.3).

**Run it from CI**

- `rai validate` without a server, and `rai run` with the GitHub Action: a failing contract blocks the pull request (FR-06.1).
- Runs on a PostgreSQL job queue that a killed worker resumes without duplicating an observation (FR-06.2).

**Test recovery with controlled chaos**

- Seven fault types through a separate chaos agent, on SandboxBank only (FR-07.1).
- Deny by default: an allow-list of targets, environments that are never production, scenario approval by a second person that expires, blast radius, and two preflights, the worker's and the agent's (FR-07.2, NFR-SAF-1).
- Every fault removed automatically, and a kill switch and watchdog that work without the API (FR-07.3, NFR-SAF-2).
- RTO, RPO from the ledger's seeding log, and consistency checks after recovery; an independent observer gives ground-truth RTO (FR-08.1, FR-08.2, FR-08.3).

**Decide with people, keep the evidence**

- Tenants, roles and row-level security; a hash-chained audit entry for every change (FR-01.1, FR-01.2, NFR-SEC-1, NFR-AUD-1).
- Findings closed only by a passing retest; waivers with an expiry; a release gate and release decisions by a named reviewer, never one's own (FR-10.1, FR-12.1, FR-12.2).
- Deterministic evidence bundles with a signed SHA-256 manifest, verified offline with `rai verify`; a human-readable report with its limitations; container images pinned by digest in every run (FR-13.1, FR-13.2, NFR-REP-1, NFR-AUD-2).
- A web UI with a dashboard whose every metric shows its definition, n and window, and a synthetic-data banner that cannot be hidden; WCAG 2.2 AA checked on every screen (FR-11.1, FR-11.2, NFR-USE-1, NFR-USE-2).

**Run it, and trust what you run**

- One command for the whole stack, tested end to end every night through journeys J1–J5 (NFR-REP-2).
- HTTPS through Caddy; structured logs, traces and health endpoints (NFR-SEC-2, NFR-OPS-1).
- Images pinned by digest, with an SBOM, a blocking vulnerability scan and a keyless cosign signature (NFR-SEC-3); a versioned STRIDE threat model (NFR-SEC-4).

## Verify this release

Each release has, attached:

- the Python packages (wheels and sources), their `SHA256SUMS` and its Sigstore bundle `SHA256SUMS.sigstore.json`;
- `images.txt`: the four images by digest;
- each image's SPDX SBOM.

[Releasing](../releasing.md) gives the commands to verify the checksums, the images' signatures and SBOM attestations, and to reproduce the release yourself (`make reproduce`). The reproduction report on a clean 8 GB laptop is attached to the release.

## Limitations

- **Synthetic data only.** RAI v1.0 has been run only against SandboxBank. It is not a production tool, and the chaos agent refuses production environments by design.
- **Not built:** single sign-on (FR-01.3), "Low" priority. Findings are opened through the API, not automatically from failing rules (FR-10.1).
- **Redshift** (FR-02.2) is tested on PostgreSQL 16, not on a live cluster.
- **Deployment:** compose builds the images locally rather than pulling the signed ones, so it does not check their signatures; the worker runs on the host, not as a compose service; traffic between containers on one host is not encrypted.
- **Tamper evidence is not tamper proof:** the audit chain and the signed manifests show that something changed after the fact; they do not prevent an operator with database access from changing it (NFR-AUD-2).
