| 2026-11-13 | RAI-DRIFT | Schema drift: added, removed, renamed (removed column paired with an added one whose present values fit its type at >= 95% and whose name is similar, or a 1:1 swap), and type change (>= 50% of present values no longer fit; observed type inferred); impact from schema_change_policy; schema is a batch-level rule that fails only on breaking changes and lists every change; column order ignored | Name-only rename matching; any bad value = type change | Spec acceptance (renamed column flagged breaking); keeps a few bad values with the type rule and a changed column with schema, so one defect is not split between them; checked against D07, D08 and D09 in the sealed fixtures |
| 2026-11-13 | RAI-DUPES | Duplicates: unique/primary_key flag every occurrence after the first (count = extra copies); keys trimmed, missing parts left to required; cross-batch uses a key history per asset and rule (survives contract versions), read-only unless record=True, never compares a batch with itself; SQLite store (stdlib) with WAL, synchronous=NORMAL, 256 MiB cache and sorted keys | Flag all occurrences; Polars in-memory history; hashing keys to 64 bits | Exact, repeatable counts; 18M protocol keys do not fit comfortably in memory; hashing risks false duplicates.
